## Intent

Quien clona el repo y sigue el README al pie de la letra no puede arrancar la aplicación: la
tabla de variables de entorno documenta 4 de las 6 variables que el código lee, y las dos que
faltan (`STOCKDUAL_ENCRYPTION_KEY` y `STOCKDUAL_ADMIN_PASSWORD`) son **obligatorias** desde
FIX-0001: si no están, el arranque aborta con `IllegalStateException`. Además, la sección
"Showcase & Capturas" referencia 4 imágenes que no existen en el repositorio, así que la página
pública muestra cuatro figuras rotas.

## Reproduction Steps

1. Clonar el repositorio en limpio y levantar la base con `docker compose up -d`.
2. Seguir el README: `./mvnw spring-boot:run` sin exportar ninguna variable adicional.
3. El arranque aborta:
   `java.lang.IllegalStateException: Variable de entorno STOCKDUAL_ENCRYPTION_KEY no está
   configurada. La clave de encriptación debe proporcionarse para usar AES/GCM.`
4. Con la clave definida, vuelve a abortar por `STOCKDUAL_ADMIN_PASSWORD` (DataInitializer,
   perfiles `dev` y `default`).
5. Abrir el README en GitHub: las 4 figuras de "Showcase & Capturas" aparecen rotas porque
   `docs/screenshots/*.png` no existe ni existió nunca en el historial.

### Cambio de comportamiento documentado

El README ahora distingue explícitamente dos mecanismos que antes se confundían: **Docker
Compose** lee `.env` para interpolar `POSTGRES_PASSWORD`, mientras que **Spring resuelve
variables de entorno reales** y no lee `.env`. Esa confusión era la causa de que el onboarding
fallara incluso después de copiar `.env.example`.
