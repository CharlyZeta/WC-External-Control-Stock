## Intent
Implementar mejoras críticas de seguridad (Basic Auth, encriptación de credenciales en BD, CSP, perfiles de desarrollo) y mejoras de arquitectura/calidad (DTOs tipados, solución de N+1 queries).

## Business Rules
- BR-001: Las credenciales de WooCommerce y Gemini en DB deben encriptarse con AES/GCM utilizando la clave maestra.
- BR-002: El DataInitializer para crear el administrador inicial solo debe cargarse en perfiles de desarrollo (dev/default) y usar variables de entorno con fallback.
- BR-003: La sincronización de productos desde WooCommerce debe hacerse en lote para evitar el problema de consultas N+1 en base de datos.
- BR-004: La política de Content Security Policy (CSP) en SecurityConfig no debe permitir 'unsafe-eval' en script-src.

## Acceptance Criteria
- AC-001: GIVEN WooCommerceClient WHEN se consultan endpoints THEN se utiliza Basic Auth header en vez de query string credentials.
- AC-002: GIVEN UserSettings persistido WHEN se cargan o guardan credenciales THEN los valores en DB están cifrados en formato Base64.
- AC-003: GIVEN aplicación iniciada en prod WHEN se carga el contexto THEN el bean DataInitializer no se ejecuta.
- AC-004: GIVEN WooCommerceClient WHEN se crea un producto borrador THEN se utiliza el DTO tipado WcProductCreateRequest.
- AC-005: GIVEN WooCommerceSyncService WHEN se ejecuta syncFromWooCommerce THEN se realiza una sola consulta selectiva por SKUs a la BD.
- AC-006: GIVEN SecurityConfig configurado WHEN se evalúa el CSP THEN no se permite unsafe-eval y unsafe-inline está documentado.

## Entities Affected
- UserSettings: wcConsumerKey, wcConsumerSecret, geminiApiKey (encriptados)
- Product: repositorio optimizado con findBySkuIn
